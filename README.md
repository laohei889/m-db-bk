# MySQL /MariaDB自动备份工具 — 使用说明

## 1. 概述

**MySQL 自动备份工具**是一款 Windows 桌面应用程序，基于 PureBasic 开发。它以系统托盘图标的形式驻留后台，按预设时间自动调用 `mysqldump` 备份指定的 MySQL 数据库，并自动清理过期备份文件。

### 核心功能

| 功能 | 说明 |
|------|------|
| 定时备份 | 每天在指定时间自动执行 mysqldump |
| 过期清理 | 自动删除超过保留天数的旧备份文件 |
| 系统托盘 | 最小化到托盘，不占用任务栏 |
| 日志记录 | 按日期生成日志文件，记录每次操作 |
| 系统服务 | 可安装为 Windows 服务，开机自动运行 |
| 单实例保护 | 防止重复启动 |

---

## 2. 系统要求

- **操作系统**：Windows 7 / 8 / 10 / 11 / Server 2008+（x86 或 x64）
- **运行时**：无需额外运行时，编译后为独立可执行文件
- **依赖**：需要 `mysqldump.exe`（MySQL 官方客户端工具）
  - 可从 [MySQL 官网](https://dev.mysql.com/downloads/) 下载 MySQL Community Server 或 MySQL Shell
  - 只需 `mysqldump.exe` 一个文件，无需安装完整 MySQL

## 3. 文件结构

```
程序目录/
├── MySQLBackup.exe          # 主程序
├── MySQLBackup.ico          # 托盘图标（可选，缺失时自动生成兜底图标）
├── MySQLBackup.ini          # 配置文件（首次运行后自动生成）
├── mysqldump.exe            # MySQL 备份工具（需自行放置）
├── .my.cnf.tmp              # 临时凭据文件（运行时自动创建/删除）
├── backup/                  # 默认备份目录（首次备份时自动创建）
│   ├── backup_mydb_20260721_030000.sql
│   ├── backup_mydb_20260722_030000.sql
│   └── ...
└── logs/                    # 日志目录（首次运行时自动创建）
    ├── backup_2026-07-21.log
    ├── backup_2026-07-22.log
    └── ...
```

## 4. 快速开始

### 4.1 部署

1. 将编译好的 `MySQLBackup.exe` 放到一个专用目录
2. 将 `mysqldump.exe` 放在同一目录（或稍后在设置中指定路径）
3. （可选）放置 `MySQLBackup.ico` 自定义托盘图标

### 4.2 首次配置

双击运行 `MySQLBackup.exe`，程序会最小化到系统托盘。右键点击托盘图标，选择 **「设置...」**：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 主机 | MySQL 服务器地址 | `127.0.0.1` |
| 端口 | MySQL 服务端口（1-65535） | `3306` |
| 用户名 | 数据库连接用户名 | `root` |
| 密码 | 数据库连接密码（本地编码存储） | （空） |
| 数据库 | 要备份的数据库名称（必填） | （空） |
| 备份目录 | 备份文件保存路径 | `程序目录\backup` |
| 备份时间 | 每日执行备份的时刻（时:分） | `03:00` |
| 保留天数 | 超过此天数的备份自动删除（≥1） | `7` |
| mysqldump | mysqldump.exe 的完整路径 | `程序目录\mysqldump.exe` |
| 启用每日自动备份 | 是否开启定时备份 | ✅ 开启 |

配置完成后点击 **「保存」**。

### 4.3 立即测试

右键托盘图标 → **「立即备份」**。备份成功后会弹窗提示，备份文件保存在配置的备份目录中。

## 6. 系统服务模式

### 6.1 安装为服务

**方式一：托盘菜单**

右键托盘图标 → 「安装为系统服务」→ 确认。程序会自动注册服务并启动。

**方式二：命令行（需管理员权限）**

```cmd
MySQLBackup.exe --install
```

安装成功后，服务名为 `MySQLBackupSvc`，启动类型为自动。每次 Windows 启动时会自动执行备份，无需用户登录。

### 6.2 卸载服务

**方式一：** 使用 Windows 服务管理器（`services.msc`）停止并删除 `MySQLBackupSvc`。

**方式二：命令行**

```cmd
MySQLBackup.exe --uninstall
```

### 6.3 服务模式运行

```cmd
MySQLBackup.exe --service
```

以控制台方式运行服务模式（无托盘图标），可通过 `Ctrl+C` 终止。

## 7. 备份文件命名规则

```
backup_<数据库名>_<YYYYMMDD>_<HHmmss>.sql
```

示例：`backup_mydb_20260721_030000.sql`

文件名中的 `backup_` 前缀用于区分本工具生成的备份与用户自行放置的 `.sql` 文件。过期清理**仅**删除匹配此命名规则的文件。

---

## 8. 过期清理策略

1. 程序每日备份完成后执行清理
2. 仅统计匹配 `backup_<数据库名>_*.sql` 命名规则的文件
3. 当文件数**超过**保留天数时，才执行删除
4. 使用文件**修改时间**判断是否过期（而非创建时间）
5. 文件数不超过保留天数时跳过清理，确保始终有可用备份

**示例**：保留天数 = 7，当前有 10 个备份文件
- 第 1-3 个文件（最早）已超过 7 天 → 删除
- 第 4-10 个文件 → 保留

日志文件按日期自动创建在 `程序目录\logs\` 下：

每条日志记录包含时间戳和操作内容：

## 10. 安全说明

### 10.1 凭据安全

- **进程列表**：备份时使用 `--defaults-file` 传递数据库凭据，密码不会出现在进程命令行参数中
- **临时文件**：凭据临时文件创建后立即通过 Windows ACL 限制为仅当前用户可读，备份完成后立即删除
- **配置文件**：密码在 INI 文件中经过简单编码存储（Hex+Caesar 偏移），防止无意间明文泄露

> ⚠️ **注意**：编码仅做混淆，不提供加密级安全性。如需更高安全级别，建议：
> - 使用 Windows DPAPI 或第三方加密工具保护配置文件
> - 使用 MySQL 的 `--login-path` 功能（`mysql_config_editor`）

### 10.2 mysqldump 参数

| 参数 | 说明 |
|------|------|
| `--single-transaction` | InnoDB 一致性备份，不锁表 |
| `--routines` | 包含存储过程和函数 |
| `--triggers` | 包含触发器 |
| `--events` | 包含事件调度器 |
| `--result-file` | 直接输出到文件，避免控制台编码问题 |

## 11. 配置文件格式

配置文件 `MySQLBackup.ini` 使用标准 INI 格式：

```ini
[MySQL]
Host=127.0.0.1
Port=3306
User=root
Password=00680065006C006C006F    ; 编码后的密码
Database=mydb
BackupDir=C:\backup
BackupHour=3
BackupMinute=0
KeepDays=7
DumpPath=C:\tools\mysqldump.exe
AutoBackup=1
LastBackupDate=2026-07-21
```

## 13. 常见问题

### Q: 备份失败，日志显示 "找不到 mysqldump.exe"

**A:** 确保 `mysqldump.exe` 存在于程序目录，或在设置中正确指定其路径。可从 MySQL 官网下载 MySQL Shell 或 MySQL Utilities 获取。

### Q: 备份失败，日志显示 "mysqldump 退出码 = 2"

**A:** 通常是连接参数错误。检查：
- MySQL 服务是否运行
- 主机、端口是否正确
- 用户名、密码是否正确
- 用户是否有足够的权限（需要 SELECT、LOCK TABLES、SHOW VIEW、EVENT、TRIGGER 权限）

### Q: 备份文件为 0 字节

**A:** mysqldump 可能因错误退出但未返回非零退出码。检查 MySQL 错误日志和备份目录的写入权限。

### Q: 如何备份多个数据库？

**A:** 当前版本每次配置只支持一个数据库。如需备份多个，可复制多份程序到不同目录，各自配置不同数据库，或在设置中使用逗号分隔的数据库名（需 mysqldump 支持）。

### Q: 服务安装失败

**A:** 安装服务需要管理员权限。右键程序 → 「以管理员身份运行」，然后再执行安装。

### Q: 程序被杀毒软件误报

**A:** 纯原生编译的可执行文件可能触发误报。将程序目录加入杀毒软件白名单。

## 14. 编译说明

使用 PureBasic 5.x 或 6.x 编译：

```
pbcompiler MySQLBackup.pb /EXE MySQLBackup.exe /CONSOLE
```

> 注：`/CONSOLE` 仅用于服务模式支持。纯托盘模式可不加此标志。
